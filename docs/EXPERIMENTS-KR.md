# 재현과 검증 절차

## 근거의 단계

1. [유도](THEORY-KR.md)는 비트 추출 항등식과 칸 내부의 상수성을 보인다.
2. 단위 테스트는 각 구현의 불변량과 회귀 사례를 검사한다.
3. 전수·시드 고정 실험은 유한 집합과 서로 다른 산술 경로를 확인한다.
4. 저장 마스크·언어 간 manifest는 데이터 교환을 확인한다.
5. UI·HTTP 검사는 전달·상호작용을 점검하며 수학적 증명이 아니다.

이를 형식 검증 완료, 모든 브라우저 인증, 새 자기참조 정리의 증명으로 합쳐 표현하지 않는다.

## 산술 실험 재현

```sh
python -m pip install -e .
python -m unittest discover -s tests -v
python experiments/run_suite.py
npm test
python scripts/validate_repo.py
```

실험기는 `reports/arithmetic.json`을 기록한다. 고정 시드는 **20260906**이다. 전수 크기는 `(1,1), (2,2), (3,2), (2,3), (3,3)`이며 마스크 수의 합은 658이다. 모든 마스크를 복원하고 모든 칸의 중점을 정확한 유리수 floor/mod로 검사한다. 중점 검사는 5,442회이다. 추가 무작위 마스크 300개는 더 큰 크기와 반복 위치를 확인한다. 기록된 실행은 전체 이진 칸 65,856개와 C진 배열 형상 8종을 확인했으며 불일치는 0이다.

직접 평가기는 시프트 추출을 쓰지 않지만 좌표 헬퍼는 공유한다. 두 경로에 같은 인덱스 오류가 있으면 누락될 수 있으므로 수동 A·비대칭 마스크·역사적 참조·별도 작성 JavaScript 코어로 위험을 줄였다. 어느 검사도 증명 보조기로 확인한 형식 증명은 아니다.

## 동봉 구성 실험

| 예제 | 목적 |
|---|---|
| `letter-a` | 수동 검증 기준: 3×5, N=16015, k=80075 |
| `asymmetric` | 우발적 회전·반전을 검출 |
| `historical` | 원 논문 Figure 13의 정수: 106×17, 543자리 k |
| `formula-h32` | 프로그램이 조판한 원형 부등식: 353×32, 3,380자리 k |
| `bit-h32` | 동치인 몫 기반 부등식: 193×32, 1,838자리 k |

조판 예제 두 개는 구성 사례이지 알려지지 않은 원리의 발견이 아니다. `source`는 LaTeX·렌더러 설정·버전을 기록한다. 재현에는 PNG만 두지 말고 PBM·JSON과 해시를 보존한다.

큰 생성 마스크의 원식 직접 검사는 다음과 같다.

```sh
python -m tupper_formula verify examples/formula-h32/experiment.json --literal
```

11,296개 칸 중점을 검사한다. 성공은 저장된 마스크의 정확한 일치를 뜻한다. 전수 실험의 5,442회와 별도 검사이므로 서로 바꾸어 보고하지 않는다.

## 브라우저·정적 사이트 검사

```sh
python -m pip install -e ".[qa]"
python -m playwright install chromium
python scripts/browser_smoke.py --mode http --output reports/browser-local.json
```

일반 `http` 모드는 임시 로컬 서버에서 실제 ES 모듈 로딩과 JSON 요청으로 검사한다. `--chromium PATH`로 설치된 브라우저를 지정할 수 있다. `--mode memory`는 브라우저 정책이 모든 탐색을 막는 환경에서 명시적으로 사용하는 대체 경로이다. 작성된 코드·CSS·데이터를 메모리 문서에 삽입하고 로컬 fetch·주소 갱신을 대체하여 UI를 시험한다. 이 방식은 브라우저 탐색이나 네이티브 ES 모듈 연결을 검증하지 않는다. SHA 브리지·클립보드 테스트 대역은 결과에 기록하며 실제 운영체제 클립보드 연동 성공으로 표현하지 않는다.

이 배포본의 실제 모드와 한계는 `reports/validation.json`에 있다. 정적 HTTP 경로 검사와 Node ESM 테스트는 별도의 보완 검사이다. GitHub Pages 실제 배포, 소셜 크롤러 미리보기, Firefox·WebKit 시험을 완료했다고 주장하지 않는다.

## 언어 간 데이터 교환

Node 테스트는 Python이 생성한 모든 예제를 읽어 N·k·마스크·SHA-256을 다시 계산한다. `scripts/crosscheck.py`는 JavaScript 코어로 브라우저 형식 manifest를 만든 뒤 Python 원식 평가기로 검증한다. 거대한 정수는 JSON 문자열로 유지한다. 저장된 `passed` 표시만 수정해도 잘못된 실험이 유효해지지 않으며 검증기는 불변량을 재계산한다.

## 새 실험 보고

입력 출처·권리, W/H, 이진화·크기 변경, 렌더러·라이브러리 버전, 수식 형태, 좌표 약속, 문자열 N/k, 마스크 해시, 결과 파일, 검사 방법·불일치를 기록한다. 과학적 주장과 가독성을 구별한다. 강한 자기완결적 구성에는 표현 언어, 허용 기본 연산, 글리프 규칙, 상수의 표시 방법, 동일성의 정의가 추가로 필요하다.

표준 실험기는 자기 보고서를 의도적으로 갱신하지만 실험 구성기는 기존 산출물 폴더를 덮어쓰지 않는다. 개정 비교에는 이전 보고서를 다른 파일명으로 보존한다.
